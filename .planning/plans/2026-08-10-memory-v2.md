# Memory V2 — implementation plan

> **For automated executors:** invoke `:subagent-driven-development` (recommended) or
> `:executing-plans` to run this plan task-by-task. Steps use `- [ ]` checkboxes.

**Goal:** Replace append-only thread Memory with subject-scoped, policy-controlled Memory
operations, safe session refreshes, and a Portal review workflow without adding a model call.

**TDD mode:** yes

**Architecture:** Keep the upstream `agentdc` repository read-only and implement Memory V2 in
the existing package overlay. Claude emits bounded `memory_ops` in the same answer; a Go store
service validates and applies them transactionally. Session orchestration loads separate common
and current-speaker snapshots, while the Portal exposes member/status filters and proposal
decisions through the existing authenticated local API.

**Tech stack:** Go 1.26.3, `modernc.org/sqlite` 1.54.0, standard-library HTTP/JSON, vanilla ES
modules on Node 20.9.0 and PowerShell 7.6.4 direct packaging checkpoints.

**Spec:** `.planning/specs/2026-08-10-memory-v2-design.md`

**Research:** skipped — repository-local extension with no new dependency
